## PARTE 1: CRIAR CONTA NO GITHUB

GitHub é um site onde você coloca seus arquivos na nuvem.

### Passo 1: Abrir GitHub

1. Abra seu navegador
2. Acesse: **https://github.com**
3. Você verá a página inicial do GitHub

### Passo 2: Clicar em "Sign Up"

1. No canto superior direito, clique em **"Sign up"**
2. (Ou se ver "Sign in", clique nele primeiro)

### Passo 3: Preencher o Email

1. Digite seu email (tipo: seu-email@gmail.com)
2. Clique **"Continue"**

### Passo 4: Criar Senha

1. Digite uma senha segura
   - Pode ser: `SeuNome123!`
2. Clique **"Continue"**

### Passo 5: Escolher Nome de Usuário

1. Digite um nome de usuário (será único)
   - Exemplos: `seu-nome-123`, `joao-dev`, `maria-gaming`
   - Não pode ter espaços
   - Pode ter números e hífens
2. Clique **"Continue"**

### Passo 6: Confirmação

1. Você receberá um email de confirmação
2. Abra seu email
3. Procure por um email do GitHub
4. Clique no link de verificação
5. **Pronto! Conta GitHub criada!** ✅

## PARTE 2: COLOCAR SEUS ARQUIVOS NO GITHUB

GitHub chama isso de "repositório" (um lugar para colocar seus arquivos).

### Passo 7: Criar um Novo Repositório

1. Acesse: **https://github.com** (já logado)
2. No canto superior direito, procure por um símbolo **`+`** 
3. Clique nele
4. Selecione **"New repository"**

### Passo 8: Configurar o Repositório

Você verá um formulário. Preencha assim:

**Repository name:**
- Digite: `fogo-de-proposito`

**Description:** (opcional)
- Digite: `Jogo multiplayer Fogo de Proposito`

**Public or Private:**
- Selecione: **"Public"** (assim seu amigos conseguem acessar)

**Initialize this repository:**
- Deixe DESMARCADO

Clique: **"Create repository"**

### Passo 9: Enviar Seus Arquivos

Você verá uma página vazia. Procure por um link azul que diz **"uploading an existing file"** ou uma opção de arrastar.

**Opção A: Arrastar (Mais Fácil)**
1. Pegue os 7 arquivos que você baixou
2. Selecione TODOS (Ctrl+A no Explorer)
3. Arraste até a página do GitHub
4. Soltue
5. GitHub vai fazer upload automaticamente

**Opção B: Clicar no Botão**
1. Clique em **"uploading an existing file"** (link azul)
2. Uma caixa de seleção aparecerá
3. Clique em **"choose your files"**
4. Selecione seus 7 arquivos
5. Clique em **"Abrir"**
6. GitHub vai fazer upload

### Passo 10: Confirmar Upload

1. Os arquivos aparecem na tela
2. Abaixo, clique em **"Commit changes"**
3. Aguarde (pode levar 30 segundos)
4. **Pronto! Arquivos estão no GitHub!** ✅

**Verificação:** Você deve ver seus arquivos listados:
```
server.js
package.json
public/
  └── index.html
README.md
GUIA_DETALHADO.md
HOSPEDAGEM.md
RAILWAY_5_MINUTOS.md
.gitignore
```

## PARTE 3: HOSPEDAR NO RAILWAY

Railway pega seus arquivos do GitHub e coloca online.

### Passo 11: Acessar Railway

1. Abra: **https://railway.app**
2. Você verá a página inicial do Railway

### Passo 12: Criar Conta Railway

1. Clique em **"Start a New Project"** (botão grande)
2. Selecione: **"Deploy from GitHub"**

1. GitHub vai pedir permissão
2. Clique em **"Authorize railwayapp"**
3. Pronto! Autorizado ✅

### Passo 14: Selecionar Seu Repositório

1. Você verá uma lista dos seus repositórios

### Passo 15: Confirmar Deploy

Railway vai:
1. Baixar seus arquivos
2. Instalar as dependências (`npm install`)

Quando terminar, procure por:
```

```

## 🔴 ERROS COMUNS E SOLUÇÕES

### Erro: "Build Failed"

**Possíveis causas:**
1. Falta arquivo `package.json`
2. Falta arquivo `server.js`
3. Pasta `public/` não existe

**Solução:**
1. Volte ao GitHub
2. Verifique se tem TODOS os 7 arquivos
3. Verifique se a pasta `public/` existe com `index.html` dentro
4. Faça um novo commit
5. Volte a Railway e faça novo deploy

### Erro: "Deployment Timeout"

**Significa:** Levou muito tempo

**Solução:**
1. Aguarde 5 minutos
2. Recarregue a página
3. Tente novamente

### Erro: "Port Error" ou "Address Already in Use"

**Solução:** Railway já configura a porta automaticamente. Não precisa fazer nada.

### Página Branca ou Erro 404

**Significa:** Não achou o arquivo

**Solução:**
1. Verifique se `public/index.html` está correto
2. Verifique se `server.js` está correto
3. Faça novo deploy
